MultiPCAPSearch 1.1.0 adds **live counts for captures that are still being written**.

### New: Follow growing files
Tick **Follow growing files** and the counts keep going up while Wireshark, `dumpcap -w` or `tcpdump -w` is still writing to your captures. The app streams each capture's new bytes into a tshark that keeps running, so:
- new packets are counted soon after they reach the disk (dumpcap writes them out about every 100 ms by default);
- counts always match a full re-scan, including filters that depend on earlier packets, such as `tcp.analysis.*`;
- a half-written packet at the end of a file is never shown as an error;
- if a capture is truncated or replaced, it's re-read from the start.

With **Wireshark/tshark 4.4 or newer**, one tshark process per capture handles all your filters. Older versions need one process per capture per filter, roughly 150 MB each. The status bar tells you when upgrading would help. An invalid filter only marks its own column. Italic counts mean the packets already in the file are still being read.

Following is opt-in because each tshark process stays running and uses memory. Turn it off and the last counts stay in the table.

**You still need [Wireshark](https://www.wireshark.org/download.html) installed.** MultiPCAPSearch finds its `tshark` automatically (or use *Settings > Locate tshark...*).

### Downloads
- **Windows 10/11 x64:** `MultiPCAPSearch-windows-x64.zip`. Unzip it and run `MultiPCAPSearch.exe`.
- **macOS 12+ (Apple Silicon and Intel):** `MultiPCAPSearch-macos-universal.dmg`. The app is unsigned, so right-click it and choose *Open* the first time.
- **Linux x86_64:** `MultiPCAPSearch-linux-x86_64.AppImage`. `chmod +x` it and run it.
